# Plain .tsx Lessons instead of MDX

Most docs/course sites (and Next.js's own guides) author prose content in MDX so writers can mix markdown with embedded components. We considered it, but chose plain `.tsx` pages per Lesson instead: no new content-pipeline dependency (`@next/mdx`, remark/rehype plugins), full TypeScript type-checking across prose, Demo, and Exercise in one file, and Demos/Exercises are just regular React components rather than components-imported-into-markdown. The trade-off is more verbose prose (JSX text nodes instead of markdown) and no `.md`-style editing ergonomics. Reversing this later means migrating every Lesson's prose into `.mdx`, which is a real (if mechanical) cost — worth recording so a future reader doesn't "fix" this by reaching for MDX without knowing it was deliberate.
